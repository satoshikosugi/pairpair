# PairPair 改善提案メモ

更新日: 2026-06-13

## 目的

PairPair を「リモート操作できる画面共有」から、日常的なペアプロ作業に耐える道具へ寄せるための追加機能案を整理する。  
音声機能は当面対象外とし、操作性・継続利用・セッション回転率への効き目が大きいものから優先順位を付ける。

## 参考にした方向性

- Tuple
  - ペアプロの進め方自体を支える設計思想を前面に出している。
  - 参考: https://tuple.app/pair-programming-guide
- Visual Studio Live Share
  - `Focus and Follow`、共同編集、共同デバッグ、shared terminals / servers など「共同作業の文脈同期」が強い。
  - 参考: https://visualstudio.microsoft.com/services/live-share/
- AnyDesk
  - `Session Permission Profiles`、`Permission Management`、`Session Requests`、`Whiteboard` など、遠隔操作時の権限整理と補助機能が整理されている。
  - 参考: https://anydesk.com/en/features
- TeamViewer
  - `Screen sharing`、`Wake-on-LAN`、各種 integration など、継続運用や周辺導線を強化する発想が強い。
  - 参考: https://www.teamviewer.com/en-us/products/remote/features/

## P1. 権限プリセットと即時切替

実装状況メモ:

- 2026-06-13 時点で MVP の一部を実装済み。
- 実装済み:
  - セッション中の権限プリセット即時切替
  - `mouse move / click / wheel / keyboard / annotation` の個別許可
  - `clipboard` 許可
  - `クリップボードのみ` プリセット
  - `フルコントロール` にクリップボード許可を含める
  - ホスト UI のプリセットボタン
  - ゲスト UI の現在制約表示
- 未実装:
  - クリップボード汚染の明示警告
  - 権限変更時のクリップボード注意喚起

### 背景

PairPair はすでに `viewOnly / controlRequested / controlAllowed / controlPaused / controlRevoked` を持っているが、実運用では「全部許可」か「全部止める」だけでは粗い。  
AnyDesk が `Session Permission Profiles` と `Permission Management` を持つのは、遠隔作業で必要な権限粒度が利用シーンごとに違うから。

### 提案

セッション中にワンクリックで切り替えられる権限プリセットを追加する。

- `閲覧のみ`
- `ポインタのみ`
- `ポインタ + クリック`
- `キーボード禁止`
- `クリップボードのみ許可`
- `注釈のみ`
- `フルコントロール`

### PairPair での効き目

- レビュー時は `注釈のみ`
- ブラウザ確認時は `ポインタ + クリック`
- シェル作業時は `フルコントロール`

のように切り替えられる。ホストの心理的負担がかなり下がる。

### MVP

- control state とは別に permission profile を導入
- `mouse move / click / wheel / keyboard / clipboard / annotation` を個別許可
- ホスト UI にプリセットボタンを追加
- ゲスト UI に現在の制約内容を明示

## P2. フォーカス同期 / 注目領域誘導

実装状況メモ:

- 2026-06-14 時点で MVP の一部を実装済み。
- 実装済み:
  - `spotlight` メッセージによる注目位置送信
  - `Ctrl + 右クリック` による注目位置送信
  - 受信側の約 3 秒ハイライト表示
  - 等倍表示時の viewport 自動スクロール補正
  - ホスト共有画面オーバーレイへのスポット表示
- 未実装:
  - 共有対象ウィンドウ切替時の `focus target changed` 表示
  - 明示的な follow モード

### 背景

Live Share の `Focus and Follow` は、共同作業の効率を上げる代表機能。  
PairPair は画面共有ベースなので、コード位置そのものは共有できなくても、「どこを見てほしいか」を高速に同期できるだけで価値が高い。

### 提案

- ホストまたは操作中ゲストが「ここを見て」を送れる
- 非操作側は一時的にその位置へ viewport を寄せる
- 可能なら共有対象ウィンドウ切替時にも `focus target changed` を表示

### PairPair での効き目

- IDE のエラー箇所
- ブラウザの特定エリア
- 設定ダイアログの特定項目

を会話なしでも素早く共有しやすくなる。

### MVP

- `spotlight` メッセージを追加
- 正規化座標で位置を送る
- ゲスト側で 3 秒程度のハイライト表示
- fit / 等倍の両方で viewport を必要に応じて補正

## P3. 共有クリップボード / スニペット送信

実装状況メモ:

- 2026-06-14 時点で MVP を実装済み。
- 実装済み:
  - テキスト限定の明示送信
  - `clipboard` 権限と `クリップボードのみ` プリセット
  - `Ctrl+V / Command+V / Shift+Insert` による相手側への貼り付け
  - 送受信履歴の表示（最大 10 件）
  - 履歴からのローカルクリップボード受け取り
- 未実装:
  - バイナリや画像の同期
  - クリップボード競合の明示警告

### 背景

TeamViewer や一般的なリモート操作ツールでは共有クリップボードが定番。  
ペアプロではファイル転送より先に、コマンド、URL、ログ断片、エラーメッセージ、diff 断片を素早く渡せる方が効く。

### 提案

- テキスト限定の共有クリップボード
- 明示操作で送る `スニペット送信`
- セキュリティを優先して明示操作のみ

### PairPair での効き目

- URL 共有
- コマンド共有
- stack trace 共有
- 一時的なコード断片共有

が極めて速くなる。音声なし前提でも共同作業が進みやすい。

### MVP

- まずはテキストのみ
- `送る / 受け取る` の明示操作
- 送受信履歴を 10 件程度表示

### 現在の使い方

1. ホストが権限プリセットで `クリップボードのみ` または `フルコントロール` など、`clipboard` が ON になるプリセットを選ぶ。
2. ホスト・ゲストの下部パネルに `クリップボード: ON` と `送る / 受け取る`、履歴欄が表示される。
3. `送る` はローカルクリップボードのテキストを相手へ共有する。これは共有クリップボード用途で、相手のローカルクリップボードへ受け渡すための操作。
4. ゲスト側の `貼り付け`、または `Ctrl+V / Command+V / Shift+Insert` は、ローカルクリップボードのテキストをホストの現在アクティブな入力先へ貼り付ける。
5. `受け取る` は直近の受信内容、または履歴内の任意項目をローカルクリップボードへコピーする。
6. 送受信履歴は最大 10 件まで表示される。

### 現在の制限

- 送信対象はテキストのみ
- ゲストからの `貼り付け` はホスト OS の現在フォーカス先に依存する

## P4. セッション再参加 / 復帰導線

実装状況メモ:

- 2026-06-14 時点で MVP の一部を実装済み。
- 実装済み:
  - `last session` のローカル保存
  - ホーム画面の `直前のセッション` 再開カード
  - ホスト設定画面の `待機セッションを再開 / ホストとして再参加`
  - ゲスト参加画面の `ゲストとして再参加`
  - エラー画面からの再開導線
  - 役割切替中は直前セッション情報を上書きせず、失敗時に元の役割へ戻る導線を維持
- 未実装:
  - セッション中の相手切断時にその場で待機し続ける再接続モード
  - 役割切替失敗ダイアログ内での `元の役割へ戻す / 再試行` 直接ボタン

### 背景

役割切替や全画面切替の安定化を進めた流れから見ても、PairPair は「短時間で壊れず戻れる」ことの価値が大きい。  
AnyDesk の `Session Requests` のように、セッション再開導線が整理されている方が実用性が高い。

### 提案

- 切断後の `再参加` ボタン
- 直前セッションの再開候補表示
- 役割切替中の失敗時に `元の役割へ戻す` または `再試行`

### PairPair での効き目

- ネットワーク揺れ
- 役割切替失敗
- 誤切断

への耐性が上がり、実作業を止めにくくなる。

### MVP

- `last session` をローカル保存
- 有効期限内なら再接続候補表示
- 役割切替は `progress / success / rollbackable failure` を明示

### 現在の使い方

1. ホストがセッションを作成するか、ゲストが参加すると、直前のセッション情報がローカルに保存される。
2. アプリをホームへ戻した後は、ホーム画面に `直前のセッション` カードが表示される。
3. ホストの場合:
   - ゲスト未接続なら `待機セッションを再開`
   - 接続済みセッションなら `ホストとして再参加`
   - 再参加時は共有先画面を再選択する
4. ゲストの場合:
   - `ゲストとして再参加` で同じセッションへ戻る
   - あいことば付きセッションは必要に応じて再入力する
5. 役割切替に失敗した場合も、切替前の直前セッション情報は残るので、ホームのカードから元の役割へ戻れる。

### 現在の制限

- ホスト再参加では共有先画面の再選択が必要
- 双方が意図的にセッションを終了した場合、そのセッションは再開できない
- サーバー側セッションが消えた場合や token が無効な場合は再参加できない
- 相手切断を検知したその場で待機し続ける再接続モードは未実装

## P5. マルチモニタ導線の強化

### 背景

ペアプロ用途では複数ディスプレイ利用が多い。  
今の PairPair でも共有対象の切替はあるが、「どの画面が今共有されているか」「別画面へすぐ切り替えたい」がもっと速い方がよい。

### 提案

- 共有中モニタの常時表示
- モニタ一覧のサムネイルストリップ
- ホットキーで次のモニタへ切替
- 最近使った共有対象の固定

### MVP

- 共有切替 UI をセッション中に即時開ける
- `前回の共有対象へ戻す`
- `screen 1 / 2 / app window` のラベルを分かりやすく表示

## P6. セッションノート / ブックマーク

### 背景

TeamViewer はセッション後の記録や運用導線が強い。  
PairPair でも、音声録音ではなく「軽いメモとタイムスタンプ」だけでも、レビュー・振り返り・引き継ぎに効く。

### 提案

- セッション中メモ
- `ここ重要` ブックマーク
- 切断時に簡易サマリ表示

### PairPair での効き目

- 後でやるタスク
- 修正箇所の記録
- 再現手順メモ

をペア内で共有しやすい。

### MVP

- テキストメモ欄
- タイムスタンプ付き追記
- エクスポートは Markdown

## P7. IDE 向け入力プリセット

### 背景

PairPair はすでにホイール方向や画質適応を持つ。  
ここをもう一段進めて、「VS Code / JetBrains / Browser / Terminal」向けの入力最適化プリセットにすると使い始めの摩擦が減る。

### 提案

- アプリ別ホイール感度
- スクロール量
- ダブルクリック猶予
- キーリピート抑制
- 文字入力優先 / ポインタ優先

### MVP

- `IDE`, `Terminal`, `Browser`, `Design Tool` の4プリセット
- ゲスト側で即時切替
- ホスト側で推奨プリセットを提示

## P8. 注釈機能の強化

### 背景

AnyDesk の `Whiteboard` は依然として有用。  
PairPair はマーカー基盤が既にあるため、拡張コストに対して効果が出やすい。

### 提案

- 一時ハイライト
- 四角 / 矢印 / 番号ピン
- `3 秒で消える` ポインタ強調
- 注釈レイヤーの保存 / 復元

### MVP

- 矢印
- 四角
- 一時ハイライト
- `全削除` とは別に `一時注釈を消す`

## 実装順の推奨

### すぐ着手すべき 3 件

1. 権限プリセット
2. フォーカス同期
3. 共有クリップボード / スニペット送信

この 3 つは、今の PairPair の設計を大きく壊さずに足せて、かつ毎セッション効く。

### 次の塊

4. セッション再参加 / 復帰導線
5. マルチモニタ導線
6. セッションノート

これは「使い勝手の良さ」と「壊れにくさ」を底上げする層。

### その後

7. IDE 向け入力プリセット
8. 注釈機能の強化

これは体験の磨き込みとして効く。

## 結論

PairPair の次の一手として最も効果が高いのは、音声追加ではなく、以下の3系統。

- 権限を細かく、安心して渡せるようにする
- どこを見てほしいかを高速に同期できるようにする
- テキスト断片や URL を軽く受け渡しできるようにする

この3つが入ると、PairPair は「一時的な遠隔操作ツール」よりも、「日常のレビュー・デバッグ・ナビゲーションに使うペアプロツール」に一段近づく。
